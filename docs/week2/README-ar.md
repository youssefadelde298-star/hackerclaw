# Week 2: الاستطلاع والجرد الأولي

## الهدف

إنتاج خريطة سطح هجوم وجرد نقاط نهاية قابل للمراجعة، ثم تسجيل فرضيات اختبار أولية لا نتائج مؤكدة. لم تُقدم ملفات المشروع نطاقًا أو حركة مرور فعلية؛ المرفقات هنا قوالب فارغة فقط.

## خطوات العمل داخل النطاق

1. راجع التصريح وسجل Week 1. إذا لم تتطابق الوجهة أو المسار أو الحساب مع النطاق، لا ترسل الطلب.
2. افتح وظائف تطبيق التدريب يدويًا بحساب المختبر، والتقط الطلبات اللازمة فقط في Burp. لا تستخدم Active Scan أو قوائم طلبات آلية كبديل عن الإذن الصريح.
3. سجّل الطريقة والمسار وأسماء المعاملات ونوع المحتوى والدور الذي شاهد الطلب وحالة الاستجابة. لا تحفظ قيم Cookies أو Tokens أو كلمات المرور.
4. ميّز بين ما شوهد في الطلب/الاستجابة وبين الاستنتاج. انقل الأصول والقيود إلى [قالب خريطة سطح الهجوم](attack-surface-map-template-ar.md).
5. استخدم [قالب جرد نقاط النهاية](endpoint-inventory-template.csv) و[سجل الاختبارات الأولية](initial-test-register-template.csv). اترك النتائج فارغة حتى يجمعها الفريق.
6. ضع لكل ملاحظة دليلًا منقحًا ومصدرًا وتاريخًا ومراجعًا. لا ترفع فرضية AI إلى Finding مؤكدة.

لمسؤوليات أعضاء الفريق، تتوفر أيضًا [مصفوفة وصول حسب الدور](access-control-matrix-template.csv) و[قالب تدفق API/منطق العمل](api-workflow-test-template.csv). استخدم أدوارًا وحسابات مختبر مصرحًا بها فقط؛ سجل ملاحظة تحديد المعدل من حركة مرور منخفضة ومسموح بها ولا ترسل حملًا آليًا.

## محاور فرز آمنة

رتّب مسارات التطبيق والـAPI حسب الوظيفة والدور بدل اختبار كل شيء عشوائيًا. دوّن أي مسارات تتعامل مع مدخلات، ملفات، جلسات، أدوار، بيانات API، أو خطوات عمل متعددة. تُجرى الاختبارات اليدوية منخفضة الأثر فقط وفق النطاق، وتُوقف عند ظهور بيانات حقيقية أو أثر غير متوقع. يمكن استخدام المهارات الموجودة في `skills/` كقوائم مراجعة، لا كإذن لتوسيع النطاق.

## الحد الأدنى لمخرج الأسبوع

- قائمة مضيفين ومسارات مع مصدر كل عنصر وحالة السماح.
- جدول نقاط نهاية وطرق ومعاملات وأدوار، بعد تنقيح القيم الحساسة.
- سجل فرضيات أولية يوضح الملاحظة وما يلزم التحقق منه، دون وصفها بأنها ثغرات مؤكدة.
- قائمة الاستثناءات والقيود والثغرات التي لم تُختبر.

## الحالة الحالية

لا توجد خريطة أو جرد Burp أو نتائج اختبار لهدف الفريق في الملفات المتاحة. لا تُملأ القوالب بعناوين مختلقة؛ شاركها مع الفريق ليضيف البيانات التي جمعها داخل المختبر المصرح به.
