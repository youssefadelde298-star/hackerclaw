# نص العرض النهائي

> المدة المقترحة: 6–8 دقائق. هذا عرض لسير العمل؛ لا تعرض اختبار هدف حقيقي إلا بتصريح مكتوب ونطاق دقيق.

## قبل العرض

- شغّل `npm run ci` وسجل التاريخ والنتيجة الفعلية.
- استخدم بيانات اصطناعية أو منقحة فقط، وأخفِ مفاتيح API وCookies وأسماء المستخدمين.
- جهّز نافذة طرفية ومثال Finding قالب، لا بيانات اعتماد حقيقية.
- لا تستخدم `--yolo`. لا ترسل طلبات إلى هدف ما لم يوافق مالك المختبر على النطاق والوقت.

## جدول العرض

1. **المشكلة والنطاق - دقيقة واحدة:** وضّح أن HackerClaw مساعد للمختبر، لا يقرر وحده وجود ثغرة. اعرض مرجع التصريح والاستثناءات دون كشف أسرار.
2. **البيئة والنموذج - دقيقة واحدة:** اعرض نسخة Node.js وموفر النموذج وtag والعتاد. إذا لم يُنفذ Benchmark محلي، صرّح بذلك ولا تعرض قياس البيئة السحابية كمقارنة.
3. **التحليل المنقح - دقيقتان:** اعرض طلبًا اصطناعيًا/منقحًا وقالبًا من `prompts/`. وضّح فصل المشاهدات عن الفرضيات وأن تحليل prompt لا يرسل طلبًا بذاته.
4. **Finding ومراجعة بشرية - دقيقة واحدة:** اعرض `examples/finding-template.json` أو نتيجة اختبار اصطناعية، مع `needs_human_review`. لا تغيّرها إلى `human_verified` في العرض.
5. **التقرير والمخاطر - دقيقة واحدة:** اعرض شكل مخرجات `/report` وحقول CVSS والأثر التجاري، وبيّن أن المتجه يختاره مقيّم وأن غياب Finding ليس استنتاجًا أمنيًا.
6. **القيود والخطوات التالية - دقيقة واحدة:** اعرض ما اختُبر فعلًا وما لم يُختبر، ونتائج retest وAI evaluation المتاحة فقط.

## خاتمة مقترحة

«يساعد HackerClaw على تنظيم التحليل والتوثيق، بينما يظل النطاق والتجربة وإثبات الأثر ودرجة المخاطر بيد المختبر البشري. النتائج التي لا تملك دليلًا وإعادة اختبار تبقى غير مؤكدة.»
