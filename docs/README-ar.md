# فهرس تسليم HackerClaw: الأسابيع 1–5

هذه الوثائق تحول خطة المقترح إلى خطوات وقوالب قابلة للتعبئة. وهي تفصل بين ما يقدمه المستودع برمجيًا وبين نتائج المختبر التي يجب أن يجمعها الفريق بنفسه. لا تُعد القوالب الفارغة أدلة أو نتائج اختبار.

## حالة الأسابيع

| الأسبوع | التسليم | الحالة الحالية |
|---|---|---|
| 1 | التخطيط وتجهيز البيئة | دليل وقائمة تحقق جاهزان؛ إعداد جهاز الفريق، اعتماد النطاق، واختيار النموذج لم تُثبت بعد. |
| 2 | الاستطلاع والاختبارات الأولية | خريطة ونماذج جرد جاهزة؛ لم يُقدَّم هدف أو تصريح أو جرد حركة مرور للفريق. |
| 3 | التحقق ودمج AI | قوالب AI ومخطط Finding وتكامل JSON موجودة. توجد ملاحظة تشغيل أولية لـQwen في بيئة مؤقتة، لا مقارنة محلية مكتملة ولا Finding لهدف. |
| 4 | المخاطر والتقارير | حساب CVSS 3.1 Base وتوليد Markdown/CSV واختباراته موجودة؛ لا توجد Finding حقيقية أو مخاطر مشروع مقيمة في الملفات المتاحة. |
| 5 | إعادة الاختبار والتقييم والعرض النهائي | قوالب retest وتقييم AI ونص العرض جاهزة. نجح `npm ci` ثم `npm run ci` على Linux/Node 22 في 2026-11-18: 695 اختبارًا عبر 68 ملف اختبار مع فحص تشغيل CLI وMCP المبنيين؛ نتائج المختبر والتقييم المحلي والعرض على جهاز الفريق ما زالت مطلوبة. |

## ما هو جاهز وما يحتاجه الفريق

- جاهز في الكود: CLI بـTypeScript/Node.js، موفرو نماذج محلية وسحابية، مكتبة prompts، مخطط Finding JSON، مراجعة بشرية، CVSS 3.1 Base، وتجميع تقرير وسجل مخاطر.
- جاهز كمواد إرشادية: قوائم الخصوصية، مهارات مراجعة مقيدة بالمختبر، وقوالب الاستطلاع وإعادة الاختبار وتقييم AI.
- مطلوب من الفريق: تحديد تطبيق تدريب مصرح به ونطاقه، توثيق إعداد Ollama/LM Studio على جهاز الفريق، قياس Qwen وLlama على الجهاز نفسه، جمع جرد حقيقي من داخل النطاق، والتحقق اليدوي من أي Finding.
- لا يوجد في الملفات المتاحة ما يثبت وجود Finding مؤكدة أو PoC لهدف حقيقي أو نتيجة retest. تقرير بلا نتائج لا يعني أن التطبيق آمن.
- نجح التثبيت النظيف بـ`npm ci`، ثم TypeScript وBiome (159 ملفًا) و695 اختبارًا عبر 68 ملفًا والبناء وفحوصات تشغيل المخرجات المبنية عبر `npm run ci`. يعرض `npm audit` خمسة تنبيهات عالية في سلسلة اعتماديات التطوير عبر `picomatch`، بينما يعرض `npm audit --omit=dev` صفرًا. الإصلاح القسري يقترح خفض Vitest إلى 3.1.4 كتغيير كاسر؛ لم يُفرض. راجع التنبيهات قبل الإصدار.

## انحرافات وتبعيات يجب حسمها

- المقترح يذكر طبقة تكامل Python، بينما التنفيذ الحالي TypeScript/Node.js. حافظنا على التنفيذ الموجود؛ يلزم اعتماد هذا الانحراف من المشرف أو قرار منفصل لبناء واجهة Python.
- سُجّل طلب القرار في [`implementation-deviation-python-typescript.md`](implementation-deviation-python-typescript.md) وحالته ما زالت **بانتظار اعتماد المشرف**؛ لم يُسجّل أي اعتماد بعد.
- المقترح لا يحدد تطبيقًا أو مضيفًا أو بيانات اعتماد مختبر بعينها. لا تُرسل حركة مرور ولا تُملأ نتائج فعلية قبل تصريح مكتوب ونطاق دقيق.
- انتقلت المسارات ومتغيرات البيئة وأسماء الأصول النشطة إلى HackerClaw؛ تبقى أسماء ومسارات PentesterFlow كمدخلات توافق مقصودة أثناء الترحيل. أضيفت اختبارات اتساق للأصول وفحوصات صياغة للمثبتات، لكن تنزيل إصدار GitHub وتشغيله وتثبيته فعليًا لم يُتحقق منه هنا؛ نجاح `npm run ci` لا يثبت جاهزية إصدار قابل للتثبيت.

## بوابة السلامة

استخدم فقط تطبيق تدريب تملكه أو لديك تصريح مكتوب لاختباره. ثبّت المضيفين والمسارات والحسابات والاستثناءات وحدود الطلبات قبل أي حركة مرور. لا تستخدم حسابات أو بيانات أشخاص آخرين، ولا تحفظ Cookies أو Tokens أو مفاتيح أو بيانات شخصية. تعامل مع اقتراح AI على أنه فرضية؛ لا تضع الحالة `human_verified` إلا بعد إعادة اختبار بشرية داخل النطاق ومراجعة دليل منقح.
