# قالب سجل مراجعة الشيفرة

> استخدمه مع مستودع أو ملفات يملك الفريق تصريحًا لمراجعتها. الملاحظة الساكنة ليست إثباتًا لوجود ثغرة قابلة للاستغلال.

## بيانات المراجعة

- مرجع التفويض والنطاق: `[يُملأ]`
- المستودع/المكون والإصدار أو commit: `[يُملأ]`
- تاريخ المراجعة والمراجع: `[يُملأ]`
- الملفات المسموح بمراجعتها: `[يُملأ]`
- أدوات التحليل والـprompt version: `[يُملأ]`

## سجل الملاحظات

| الحقل | القيمة |
|---|---|
| معرف الملاحظة | `[يُملأ]` |
| الملف والأسطر | `[يُملأ]` |
| ما يظهر في الشيفرة | `[وصف محايد، دون أسرار]` |
| شرط الوصول إلى المسار | `[يُملأ أو غير معروف]` |
| الضابط المتوقع | `[يُملأ]` |
| الفرضية الأمنية | `[يُملأ أو لا توجد]` |
| ما يلزم للتحقق التشغيلي | `[خطوة آمنة داخل نطاق المختبر أو غير متاح]` |
| دليل التشغيل المنقح | `[مرجع ملف، لا تضع بيانات اعتماد]` |
| المعالجة المقترحة | `[يُملأ]` |
| الحالة والمراجع البشري | `[needs_human_review / تمت المراجعة]` |

## قواعد الاستنتاج

- افصل صراحة بين السلوك الظاهر في الكود والافتراضات عن إعداد التشغيل أو بيانات التطبيق.
- لا تنفذ الشيفرة ولا تتصل بنظام أثناء المراجعة الساكنة.
- لا تسجل مفاتيح أو Cookies أو بيانات شخصية أو ملفات خارج نطاق التفويض.
- لا تتحول الملاحظة إلى Finding مؤكدة إلا بعد تحقق بشري مناسب ودليل قابل للتكرار في مختبر مصرح به.
- إذا لم تدعم الشيفرة ادعاءً أمنيًا، اترك النتيجة كفرضية أو أغلقها مع سبب واضح.
