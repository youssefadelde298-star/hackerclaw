# تسليم الأسبوع الثالث: AI وFinding JSON

## ما أُضيف

- `skills/week3-evidence-review/SKILL.md`: Skill للمراجعة المبنية على الدليل داخل مختبر مصرح به، مع حدود واضحة ومراجعة بشرية.
- `skills/sqli/SKILL.md`: منهجية يدوية آمنة لـSQLi تشمل In-band وBlind وBoolean-based وTime-based وUNION-based، مع منع استخراج بيانات حقيقية.
- `prompts/`: مكتبة قوالب v1 للاستطلاع وتحليل Finding ومراجعة الكود وصياغة التقرير.
- `schemas/finding-v1.schema.json`: عقد JSON موحّد لنتائج المشروع.
- `examples/finding-template.json`: قالب فارغ فقط، وليس Finding حقيقيًا.
- `src/findings/store.ts`: حفظ JSON جانبي مع Markdown، ومعرّف فريد لكل اسم متكرر، وحالة JSON تبدأ بـ`needs_human_review`.
- `src/tools/finding.ts`: طلب method وresponse excerpt وخطوات إعادة الاختبار، وإظهار موافقة بشرية قبل الحفظ.
- اختبارات التغييرات في `src/findings/store.test.ts` و`src/tools/finding.test.ts`، وتصحيح استنتاج POST لطلبات curl ذات الجسم في `src/findings/httpRequest.ts`.
- `docs/week3/privacy-ethics-checklist-ar.md`: قائمة تحقق للخصوصية والأخلاقيات.
- `docs/week3/local-model-benchmark-ar.md`: نتيجة smoke أولية وجدول مقارنة محلية لـQwen وLlama.

## التشغيل بمفتاح API

```sh
npm ci
npm run dev
```

من داخل التطبيق:

1. اختر `minimal` إذا ظهر سؤال مستوى الأدوات.
2. اكتب `/provider` واختر الخدمة التي ينتمي إليها مفتاحك.
3. أدخل المفتاح في نافذة الإدخال المقنّعة، ثم اختر نموذجًا من القائمة.
4. جرّب رسالة غير حساسة مثل `رد بكلمة READY فقط`.

يدعم الاختيار التفاعلي Kimi وGroq وGemini وClaude/Anthropic وOpenRouter وDeepSeek. خيار `openai-compat` يحتاج عنوان API ومفتاحًا مضبوطين مسبقًا. يُحفظ المفتاح محليًا في `~/.pentesterflow/config.json` بصيغة غير مشفّرة؛ لا تشارك الملف أو المفتاح. الطلبات المرسلة إلى مزود سحابي تغادر جهازك، لذلك لا تستخدم بيانات حقيقية أو أسرارًا.

لتشغيل فحوصات المشروع قبل العرض، نفّذ `npm run ci`. ولربط Burp، شغّل `/burp 9999` داخل التطبيق ثم اربط الإضافة بعنوان الاتصال والرمز اللذين يعرضهما.

## حالة متطلبات الأسبوع الثالث

| المتطلب | الحالة |
|---|---|
| دمج أول مكوّن AI وإخراج Finding موحّد بصيغة JSON | الكود والقالب والاختبارات جاهزة؛ يلزم تشغيلها في بيئة الفريق |
| Finding مؤكدة وPoC ودليل داعم من تطبيق مصرح به | غير مكتمل؛ يحتاج مختبر الفريق وإعادة اختبار بشرية |
| عرض أول مسار End-to-End على هدف الفريق | غير مكتمل؛ لم يتصل هذا العمل بهدف فعلي ولم ينشئ Finding مؤكدة |
| Benchmark مقارن لـQwen وLlama على جهاز الفريق | غير مكتمل؛ الملف يحتوي قياس smoke مؤقتًا وجدولًا لتسجيل القياسات المحلية |

المقترح يشترط نموذجًا محليًا (Ollama أو LM Studio) وBenchmark لـQwen/Llama. استخدام API key مفيد لتجربة واجهة المزود، لكنه لا يستبدل القياس المحلي. القياس المؤقت في `local-model-benchmark-ar.md` تم في بيئة سحابية وليس على جهازك.

## خطوات إكمال العرض

1. اختَر تطبيق تدريب مصرحًا به، واكتب المضيف والمسارات والحسابات المسموح بها.
2. شغّل HackerClaw، واضبط المزود بـ`/provider`، وحدد الهدف بـ`/target <رابط المختبر>`.
3. اكتب `/week3-evidence-review` لتحميل قواعد المراجعة.
4. قدّم طلبًا واستجابة منقحين من هدفك فقط. لا تطلب من AI إرسال طلبات من تلقاء نفسه.
5. أعد اختبار الفرضية يدويًا داخل النطاق، وسجّل PoC وخطواته ولقطة/استجابة منقحة.
6. بعد التحقق البشري، استخدم `confirm_finding` ووافق على نافذة الإذن. لا تستخدم `--yolo`.
7. تأكد من وجود `findings/<slug>.md` و`findings/<slug>.json` وراجع الحقول والدليل. الحالة تبقى `needs_human_review` إلى أن يغيرها المختبر يدويًا بعد مراجعته.

ملاحظة: المستودع مبني بـTypeScript، بينما يقترح ملف المشروع طبقة تكامل Python؛ يلزم تأكيد قبول HackerClaw كبديل مع المشرف.

## ما تم اختباره في بيئة العمل هذه

- تم تنزيل وتشغيل Ollama 0.40.11 وQwen3:4b محليًا في بيئة اختبار مؤقتة.
- اجتاز `npm run ci` كاملًا: TypeScript، وBiome على 151 ملفًا، و63 ملف اختبار تضم 661 اختبارًا، ثم بناء `tsup`.
- أعاد اختبار Ollama النصي `READY`، كما أعاد استدعاء الأداة التجريبية `week3_smoke_check` بالوسيط `{"status":"ready"}`. لم تُنفذ الأداة ولم يُرسل أي طلب أمني.
- ظهر في خرج Qwen3 مقطع `<think>` قبل الرد/استدعاء الأداة؛ HackerClaw يزيل وسوم التفكير من الخرج قبل عرضه أو حفظه.
- لم يُختبر أي موقع أو مختبر فعلي، ولم تُنشأ Finding مؤكدة. جميع بيانات الاختبارات ملفات وهمية منقحة.
- يترك خرج الذكاء الاصطناعي الحالة `needs_human_review` دائمًا؛ لا يغيّرها إلى `human_verified` إلا المختبر يدويًا بعد إعادة الاختبار ومراجعة الدليل في نطاق مصرح به.

قبل التسليم النهائي للفريق، أضف Finding حقيقية من مختبركم فقط بعد إعادة إنتاجها يدويًا، واحذف أي أسرار من الدليل.

## متابعة إصلاحات Windows والتبعيات

- عولجت اختبارات المسارات والحفظ المتزامن ورسائل PowerShell بحيث تراعي Windows؛ اختبارات أوامر Unix فقط تُشغّل على أنظمة Unix. أُعيد فحص الكود والاختبارات والبناء على Linux، ويلزم إعادة `npm run ci` على جهاز Windows للتأكيد هناك.
- شُغّل تحديث أمني غير قسري للتبعيات التي لها إصلاح متوافق مع الإصدارات الحالية؛ انخفض تقرير `npm audit` من 21 إلى 7 تنبيهات. ستة تخص أدوات التطوير والاختبار، وواحد عالٍ في Zod يتطلب ترقية رئيسية إلى Zod 4. لم يُستخدم `npm audit fix --force` لتجنب تغييرات كاسرة غير مختبرة.
