# Week 1: التخطيط وتجهيز البيئة

## الهدف

تجهيز طريقة عمل قابلة للتكرار قبل جمع أي حركة مرور: اعتماد نطاق مكتوب، تحديد مختبر التدريب، إعداد HackerClaw وموفر نموذج محلي، وتوثيق قيود الخصوصية. لا يوجد في المستودع تصريح أو هدف مختبر محدد نيابة عن الفريق.

## إعداد نسخة المصدر

المتطلبات الأساسية لتشغيل المصدر وفحوصات المشروع: Node.js 20 أو أحدث وnpm. يتطلب بناء الملفات التنفيذية المستقلة Bun. استخدم مجلدًا نظيفًا ولا تضع ملفات نتائج أو أسرارًا داخل Git.

```sh
npm ci
npm run ci
npm run dev
```

لتجربة موفر محلي، ثبّت Ollama أو LM Studio على جهاز الفريق، واختر نموذجًا مناسبًا لذاكرته. مثال Ollama المذكور في README:

```sh
ollama pull qwen3:4b
```

داخل التطبيق اختر موفر Ollama من `/provider`، ثم اختر النموذج عبر `/model`. استخدم طلبًا نصيًا غير حساس مثل `Reply with READY only` لاختبار الاتصال. لا تستخدم بيانات الهدف في اختبار الاتصال. توثيق المقارنة المحلية موجود في [Week 3](../week3/local-model-benchmark-ar.md)؛ تشغيل واحد أو بيئة سحابية لا يحل محل قياس الجهاز الفعلي.

## سجل التخطيط المطلوب

املأ هذه الحقول مع مالك المختبر قبل أول اختبار:

| الحقل | قيمة الفريق |
|---|---|
| مالك التطبيق وجهة التصريح | `[يُملأ]` |
| اسم تطبيق التدريب وإصداره | `[Juice Shop أو DVWA أو مختبر معتمد آخر]` |
| المضيفون والبروتوكولات المسموحة | `[يُملأ بدقة]` |
| المسارات والـAPIs المسموحة | `[يُملأ بدقة]` |
| الحسابات والأدوار المخصصة للفريق | `[حسابات مختبر فقط]` |
| الأنظمة والوظائف المستثناة | `[يُملأ]` |
| حد الطلبات ونافذة الاختبار | `[يُملأ]` |
| نقطة الاتصال عند أثر غير متوقع | `[يُملأ]` |
| قرار معالجة البيانات وإرسالها إلى AI | `[محلي / بيانات اصطناعية / سياسة معتمدة]` |

احتفظ بنسخة من التصريح وموافقة المشرف في مخزن الفريق الآمن، لا في مستودع عام.

## معمارية العمل المقترحة

1. يجمع المختبر حركة مرور طبيعية من التطبيق المصرح به عبر المتصفح وBurp.
2. تُنقح الطلبات والاستجابات وتُزال منها الأسرار قبل مشاركتها مع AI أو حفظها.
3. يحلل HackerClaw البيانات التي يختارها المختبر؛ لا يُعد اقتراح النموذج دليلًا.
4. يعيد مختبر بشري التحقق يدويًا، ثم يحفظ Finding JSON بموافقة بشرية.
5. يجمع `/report` السجلات المنقحة في مسودة تقرير وسجل مخاطر.

## قائمة تحقق القبول

- [ ] Node.js/npm يعملان على جهاز الفريق وسُجلت الإصدارات.
- [ ] نجح `npm run ci` على جهاز الفريق، وسُجلت النتيجة وتاريخها.
- [ ] تم توثيق موفر AI محلي وإصدار النموذج والعتاد؛ لم تُرسل أسرار إلى مزود سحابي.
- [ ] يوجد تصريح مكتوب ونطاق دقيق واستثناءات وحدود اختبار.
- [ ] مراجعة الإذن البشرية مفعلة؛ لا يُستخدم `--yolo` في العرض أو الاختبار.
- [ ] اتفق الفريق مع المشرف على انحراف Python في المقترح: التنفيذ الحالي TypeScript/Node.js.

## الحالة الحالية

المستودع يحتوي على كود التطبيق واختباراته وتعليمات نموذج مبدئية. لم تُثبت هذه البيئة إعداد جهاز الفريق أو اختيار Qwen/Llama النهائي أو تصريح مختبر؛ اترك العناصر أعلاه غير محددة حتى يقدمها الفريق.
